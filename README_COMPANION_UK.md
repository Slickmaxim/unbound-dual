# gpSP Pokémon — Unbound Companion v4

Проєкт на основі **gpSP 3D v0.1.7**, commit `717b5372f3bd9f613017d3aa71630fdbc5cea7a2`. Нижній екран використовує читачі та інтерфейс PokeDaisy. JIT, звук, верхній екран, 3D, звичайні save і save states обслуговує gpSP.

## Встановлення одного CIA

1. Скопіюй `cia/gpsp-pokemon-pokedaisy.cia` з архіву на SD та встанови через FBI. Окремий CIA-ярлик більше не потрібен.
2. Відкрий **Pokémon Unbound** у HOME Menu. Під час першого запуску вибери свій **Unbound 2.1.1.1 English** у браузері. START скасовує вибір і закриває застосунок.
3. Наступні запуски одразу відкривають вибраний ROM. Гра стартує звичайно: продовжуй через її **Continue**. Save state автоматично не завантажується.
4. Змінити ROM можна під час гри: **MENU → System → Unbound ROM: Select ROM**. Зміна діє на наступний запуск, поточна гра продовжується.

ROM не входить до CIA. Він і збереження залишаються на SD. Якщо ROM переміщений, застосунок знову попросить його вибрати. Звичайний gpSP 3D не замінюється.

Title ID застосунку: `000400000BAC8200`, той самий, що у Unbound Companion v3; версія CIA підвищена до 0.0.4. Новий CIA оновлює v3 та перейменовує його іконку на **Pokémon Unbound**. Якщо раніше встановлено окремий ярлик v3, він більше не потрібен; видалити можна саме старий ярлик із title ID `000400000BAC8300`. Конфіг, кеш і збереження не потрібно переносити.

Використовується нейтральна іконка та банер gpSP. Для Homebrew Launcher є `3ds/gpsp-pokemon-pokedaisy.3dsx` із таким самим автозапуском. Companion вмикається автоматично; його параметри доступні через MENU.

## Налаштування та збереження

Конфіг нашої версії: `SD:/3ds/gpsp3d/companion-gpsp3d.cfg`. За його відсутності початкові параметри читаються зі старого `gpsp3d.cfg`; надалі конфіги незалежні. Файли профілів gpSP для окремих ігор залишаються штатними.

Нові ключі:

```ini
companion_rom=sdmc:/roms/gba/Pokemon Unbound.gba
companion_dark=0
companion_filter=0
```

`companion_rom` можна редагувати вручну, коли застосунок закритий. Вказуй повний шлях `sdmc:/...`. Назва ROM довільна; для збережень важливі його назва та налаштована папка.

- **Display → Companion theme → Light / Dark** — світле/темне оформлення PokeDaisy, початково Light. Спрайти й карта зберігають власні кольори.
- **Display → Companion filtering → Nearest / Smooth** — фільтр масштабованих карток нижнього екрана, початково Nearest. Карта вже малюється найближчим пікселем, картка тренера — у природному розмірі; текст не розмивається.
- **Display → Scaling → Nearest (no filter)** — окремий фільтр **верхнього** екрана. При дробовому масштабі Fit/Stretch розміри пікселів можуть чергуватися.

Розташування `.sav`/`.srm`, розширення, пошук наявних файлів і слоти станів визначає gpSP. Companion не має власного записувача save та не змінює RAM гри. Перед перенесенням ROM збережи його поточний save; сам ярлик перенесення не потребує.

## Підготовка та кеш

Перший запуск перевіряє SHA-1 ROM, знаходить графіку, готує карту й записує кеш. На екрані показуються етапи та відсоток перевірки/сканування. Перший пошук на O3DS може бути тривалим.

Повторні запуски перевіряють ROM і читають готові ресурси з `SD:/3ds/gpsp3d/companion-cache/<sha1>-v3.bin`. Повного повторного пошуку графіки немає. Коли запис ідентичності ROM збігається з поточним файлом, використовується швидка перевірка. Після зміни ROM чи за відсутності запису виконується повний SHA-1.

Кеш містить лише графіку та геометрію карти, без даних поточного save. Пошкоджений або несумісний кеш перебудовується. Якщо запис на SD не вдався, гра може працювати, але наступна підготовка знову буде повною. Для ручної перебудови можна видалити кеш, коли застосунок закритий.

Нові кеш-записи й журнал підготовки виконуються до емуляції. Під час гри companion не читає/пише кеш. У відкладеному журналі рядок `Companion v4` містить `cache hit`, `rebuilt` або `not saved` та час `prep ... ms`.

## Вкладки

- **PARTY:** команда, рівні, HP, статуси, атаки/PP, характеристики та інформація про покемона.
- **BAG:** кишені, прокручування, кількості, назви й описи предметів.
- **MAP:** карта Borrius із ROM, позиція, сторінки та PLACES.
- **CARD:** картка тренера за реалізацією PokeDaisy для Unbound; дотик перегортає сторону. Час не блимає й анімаційного стискання немає, щоб уникнути регулярних перемальовувань. Без завантаженого save чи потрібної графіки показується пояснення.
- **MENU:** штатне меню gpSP із його налаштуваннями.

Усі вкладки лише для перегляду: без USE/GIVE/TAKE, редагування команди, PC чи FLY. DEX і бойове керування не додаються. Штатні Simple, Performance та Off after 10 s доступні.

Підтримується лише Unbound 2.1.1.1 English, SHA-1 `b4776b82a4c7915d0fadeaa27e013523f99dfd94`. Для інших ROM gpSP працює, а Companion повідомляє про відсутність підтримки.

## Пам'ять і швидкість

Companion не створює другої 32 MiB копії ROM. Його динамічна пам'ять обмежена 2 MiB, включно з буферами карти, картки та малювання. Під час гри він читає RAM і резидентні ROM-сторінки без викликів paging/JIT. Відсутня сторінка означає недоступні дані.

Оновлення максимум 5 разів/с, із зменшенням частоти до 2/1 разу/с за високої вартості роботи. Малюється лише поточна вкладка після видимої зміни або дотику. Лічильник кадрів не перемальовує незмінну команду/інвентар/карту.

Користувач підтвердив роботу вкладок v1 на консолі, але повідомив про статтер кожні 2–3 с. v2 прибрав зайве перемальовування; v3 додав кеш/оформлення/картку; v4 об’єднує запуск в один CIA. v4 ще потребує апаратного тесту. Повідомлені 60 FPS звичайного gpSP на O3DS у 2D не є вимірюванням цієї версії.

## Збірка та перевірки

```sh
make -C 3ds 3ds
bash gpsp3ds/companion/test/run.sh /path/to/pokedaisy/app/src/test/resources/fixtures
python3 gpsp3ds/companion/test/verify_cia.py gpsp3ds/out
```

Docker-образ `devkitpro/devkitarm:latest`; скрипт отримує офіційні makerom 0.18.4 і bannertool 1.2.2 у локальний ігнорований каталог `.cia-tools`. Збирається лише PokeDaisy companion.

Host-тести перевіряють два знімки RAM Unbound, HP/команду, дані картки, дотики, тему, незмінність RAM, очищення пам'яті; синтетичний ROM — межі блоків, карту, кеш і його помилки; тест масштабування — збереження палітри у Nearest. Перевірка CIA контролює хеші, title ID, версію, назву та маршрут запуску. Ці тести не виконують справжній ROM Unbound і не вимірюють FPS ARM11.
